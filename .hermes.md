# crypto-trading-bot — Hermes project rules

## Decision quality (BoN / LLM verifier) — mandatory load

When **any** of the following is true, **before** giving a single recommended next task or approach:

1. Call `skill_view(name='best-of-n-verify')`
2. Run the skill procedure (freeze criteria → N=3 angled gens → score → margin gate)
3. Do **not** invent a lone “winner” if margin &lt; 1.5 — escalate + optional ground-truth

**Triggers**

- Staff / priority: “staff next”, “which gap”, “what should we work on”, bang-for-buck among scale gaps
- Explicit fork: “A vs B”, “pick between”, ≥2 OPEN/QUEUED competing MASTER items
- Approach fork: ≥2 plausible code/design paths with real cost of being wrong
- Promote readiness: competing analyst packets / go-no-go with disagreement
- User says BoN / verifier / best-of-n / MASTER `bon_verify: true`

**Skip BoN**

- User already locked one option (“do GAP-05”, “execute C”)
- Single-path bugfix or firefight with one clear RCA
- Live order / capital / TP / SL / USDC / mid-cycle changes
- Routine ops triage / cron noise

**After pick:** execute winner; stage runner-up as backup when indeterminate.

Pilot reference: `reports/bon_verify_pilot/`  
Rank helper: `~/.hermes/skills/software-development/best-of-n-verify/scripts/score_candidates.py`
