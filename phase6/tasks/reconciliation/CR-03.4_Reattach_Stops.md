# CR-03.4: Re-attach Fresh Stops Post-Rebalance

**Parent:** CR-03  
**Status:** Ready for delegation  
**Priority:** High  
**Depends on:** CR-03.3

## Problem
After rebalancing, new positions need fresh protective stops.

## Desired Behavior
After rebalance completes, create new stop-loss orders on the resulting positions using current RiskEngine parameters.

## Scope (In)
- Calculate appropriate stop prices for new positions
- Submit new stop orders via `StopLossManager` / `OrderExecutor`
- Log new order IDs

## Scope (Out)
- Rebalance execution (CR-03.3)
- Detection and suspension logic

## Success Criteria
- New stops are attached to all rebalanced positions
- Stop parameters follow current RiskEngine rules
- No orphaned stops remain

## Validation
- After rebalance, query exchange or `StopLossManager` confirms new stops exist
- Logs show new stop order IDs linked to new positions

- `phase6/core/phase6_runner.py`
- `phase6/core/stop_loss_manager.py`
- `phase6/core/order_executor.py`
