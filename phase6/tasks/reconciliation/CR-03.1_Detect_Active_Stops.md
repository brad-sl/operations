# CR-03.1: Detect Active SL/TP Orders Before Rebalance

**Parent:** CR-03  
**Status:** Ready for delegation  
**Priority:** High

## Problem
The rebalance method has no visibility into currently active stop-loss or take-profit orders.

## Desired Behavior
Before executing any rebalance, the system must detect and list all active SL/TP orders for the pairs in the current basket.

## Scope (In)
- Query active orders via `StopLossManager` or exchange client
- Return a structured list of active protective orders per pair
- Log the detected orders

## Scope (Out)
- Suspending or canceling orders (CR-03.2)
- Any rebalance logic

## Success Criteria
- `_perform_daily_rebalance()` can call a method that returns active stops
- Logs show detected orders before rebalance begins
- No breaking changes to existing rebalance flow

## Validation
- Manual trigger of rebalance shows active stops in logs
- Unit test (or manual check) confirms detection works for at least one pair with an active stop

## Files
- `phase6/core/phase6_runner.py`
- `phase6/core/stop_loss_manager.py`
