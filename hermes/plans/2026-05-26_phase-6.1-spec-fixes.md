# Phase 6.1 Unified Feature Specification — Flaw Resolution Plan (Updated)

**Goal:** Produce a corrected, unambiguous Phase 6.1 spec with bootstrap + recurring Capital Allocation, sticky rebalancing, withdrawal reserves, and deterministic behavior across Fresh Start and Takeover scenarios.

## Withdrawal Flagging Mechanism (NEW)

**Purpose**: Allow the investor to explicitly reserve USD for withdrawal (e.g., to pay bills) so the system never deploys it.

**Design**:
- Investor flags an amount via Telegram command or UI: `/withdraw_reserve 2500`.
- System records in `cycle_state.json`:
  - `withdrawal_reserved_usd`
  - `withdrawal_reserved_at`
  - `withdrawal_target_date` (optional)
- `deployable_usd` = total USD balance − `withdrawal_reserved_usd` − open commitments.
- Reserved amounts are **never** touched by Capital Allocation, Rebalancing, or Rotation.
- Reservation is cleared when the investor executes the external withdrawal.
- 14-day stale reservation → alert only (no auto-release).

This mechanism applies uniformly to Withdrawal, Capital Allocation, and Rebalancing flows in both Fresh Start and Takeover scenarios.

## Architecture Update: Fresh Start Descope + Capital Allocation

**Fresh Start** = bootstrap only
- One-time (or rare) initial setup.
- Establishes baseline 5 pairs + weights.
- Not run on a daily or recurring basis after bootstrap.

**New Capital Allocation** = primary recurring deployment engine
- Trigger: Event-driven on detected USD inflow/liquidation, or scheduled every 15–30 min.
- Logic:
  1. Load `cycle_state.json` (includes withdrawal reserves and current sticky weights).
  2. Calculate `deployable_usd`.
  3. If above minimum trade size, select optimal pairs while respecting existing rebalanced allocations.
  4. Deploy and immediately place new positions under the rebalancing regimen.
- Never deploys reserved withdrawal funds.
- Works the same after bootstrap or during Takeover of an existing portfolio.

**Execution Order (ongoing)**:
1. Withdrawal Reserve Check
2. Capital Allocation (new deployable USD)
3. Weekly Rebalancing (if due)
4. Opportunistic Rotation (if triggered)

All flows (Withdrawal, Capital Allocation, Rebalancing) are consistent across bootstrap and takeover.
