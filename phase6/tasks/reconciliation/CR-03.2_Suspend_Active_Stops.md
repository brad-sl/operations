# CR-03.2: Suspend Active Stops Before Rebalance

**Parent:** CR-03  
**Status:** Ready for delegation  
**Priority:** High  
**Depends on:** CR-03.1

## Problem
Active stop orders can interfere with rebalance trades or leave orphaned stops after positions change.

## Desired Behavior
After detecting active stops (CR-03.1), the system must suspend/cancel them before proceeding with rebalance.

## Scope (In)
- Cancel or mark as suspended all active SL/TP orders for pairs being rebalanced
- Record which stops were suspended
- Maintain audit trail

## Scope (Out)
- Rebalance execution (CR-03.3)
- Re-attaching new stops (CR-03.4)

## Success Criteria
- No active stops remain on pairs that will be rebalanced
- Suspended stops are logged with order IDs
- System can proceed to rebalance without stop interference

## Validation
- After suspension step, query confirms no active stops on affected pairs
- Logs clearly show which orders were suspended
